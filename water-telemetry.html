Water vending machine telemetryТелеметрия автоматов розлива воды

STM32 + ESP32 · MQTT · Python · PostgreSQL · Docker

A client operates a network of water vending machines. Each machine is controlled by an STM32 board; I added an ESP32 Wi-Fi gateway and built a server that collects temperatures, water consumption and machine status from the whole fleet, stores the history and alerts operators about problems.

У заказчика сеть автоматов розлива воды. Каждым автоматом управляет плата на STM32; я добавил Wi-Fi-шлюз на ESP32 и сделал сервер, который собирает с парка аппаратов температуры, расход воды и состояние, хранит историю и сообщает операторам о проблемах.

System architectureАрхитектура системы

The STM32 board keeps doing its job — controlling the machine and counting water in flash. The ESP32 talks to it over UART and connects to the server's MQTT broker over Wi-Fi. Operators work in the web interface and get alerts in Telegram and by e-mail.

Плата STM32 продолжает делать своё дело — управляет автоматом и хранит счётчик воды во flash. ESP32 общается с ней по UART и подключается по Wi-Fi к MQTT-брокеру сервера. Операторы работают в веб-интерфейсе и получают тревоги в Telegram и по e-mail.

Polling cycleЦикл опроса

The server decides when to ask — machines don't flood it with data. One request goes through the broker to a specific machine, the ESP32 queries the STM32 board with the board's existing text protocol and publishes the answer back. No changes to the machine firmware were needed.

Когда спрашивать, решает сервер — аппараты не засыпают его данными. Запрос уходит через брокер конкретному аппарату, ESP32 опрашивает плату STM32 по её существующему текстовому протоколу и публикует ответ обратно. Прошивку автомата менять не пришлось.

DeploymentРазвёртывание

The server runs in Docker Compose: the same setup works on a developer PC and on a cloud VM. Data lives in volumes, so containers can be updated or rebuilt without losing anything; the database is backed up daily.

Сервер работает в Docker Compose: одна и та же конфигурация запускается на компьютере разработчика и на облачной виртуальной машине. Данные хранятся в томах, поэтому контейнеры можно обновлять и пересобирать без потерь; база копируется ежедневно.

DetailsПодробности

  • Zero-touch onboarding: all machines share one device login; a new machine connects on its own (client ID = STM32 UID) and appears under “New devices”, where the operator registers it.
  • Isolation: broker ACL lets each machine write only to its own topics water/v1/<UID>/….
  • Data: two temperatures, water counter (liters), status word with leak / no water / low level flags, flow rate.
  • Alerts: leaks, no water, lost connection, counter going backwards — in Telegram and by e-mail.
  • Testing without hardware: a simulator runs any number of virtual machines and injects faults (leak, link loss, board not responding).
  • Подключение без настройки: у всех аппаратов общий логин; новый аппарат подключается сам (client ID = UID STM32) и появляется в «Новых аппаратах», где оператор его регистрирует.
  • Изоляция: правила брокера (ACL) позволяют аппарату писать только в свои топики water/v1/<UID>/….
  • Данные: две температуры, счётчик воды (литры), слово состояния с флагами протечки, отсутствия воды и низкого уровня, расход.
  • Тревоги: протечка, нет воды, потеря связи, счётчик пошёл назад — в Telegram и по e-mail.
  • Проверка без железа: симулятор запускает любое число виртуальных аппаратов и имитирует неисправности (протечка, обрыв связи, плата не отвечает).
